# معمارية الأمن — مسودة المرحلة B

**الحالة:** مسودة للمراجعة والاعتماد  
**المرجع:** [تقرير التدقيق](./PROJECT_AUDIT.md)

## أهداف الحماية

- عزل صارم بين المجموعات والمنشآت والبيانات التابعة لها.
- منع تنفيذ عمليات دون هوية وصلاحية ونطاق بيانات صالح.
- حماية الأسرار والبيانات الشخصية والمالية وسجلات التدقيق.
- إمكانية تتبع الموافقات والتعديلات والتصدير والاستعادة.

## حدود الثقة

1. المتصفح ومدخلاته غير موثوقة، حتى للمستخدم المسجل.
2. API هي نقطة التفويض والتحقق؛ إخفاء رابط أو زر في الواجهة ليس صلاحية.
3. خدمة Supabase ذات service role تتجاوز RLS؛ تستخدم في الخادم فقط وتحتاج استعلامات مقيدة بـcompany/group لكل عملية.
4. قاعدة البيانات تفرض المفاتيح الأجنبية والقيود الفريدة والفحوصات اللازمة، ولا تعتمد على تحقق الواجهة.
5. الأسرار تحفظ في إعدادات البيئة أو مدير أسرار الاستضافة؛ لا ترسل عبر الدردشة أو المستودع أو سجلات الأخطاء.

## الهوية والجلسات

- مراجعة اختيار آلية المصادقة قبل الإنتاج، مع دعم MFA وسياسة استعادة آمنة.
- Cookies: `HttpOnly`, `Secure` في الإنتاج، `SameSite` مناسب، مدة انتهاء قصيرة، وإبطال الجلسة عند تعطيل الحساب أو تغيير كلمة المرور.
- فرض Rate limiting وتسجيل محاولات الدخول دون حفظ كلمات المرور أو الرموز.
- كلمات المرور ذات تخزين بطيء مملح؛ لا تطبعها في سجل أو رسالة خطأ.

## التفويض

- استخدام RBAC للأدوار، وABAC لسياق الشركة/الفرع/القسم/نوع السجل/قيمة العملية.
- التحقق من فعل محدد لكل API؛ لا يكفي دور عام أو اسم منصب.
- فصل الصلاحيات عن المسمى الوظيفي، وتطبيق Segregation of Duties على الاعتماد والترحيل.
- التفويض المؤقت له نطاق ومدة ومانح ومستلم وسجل إلغاء.
- لا تكشف رسائل الإشراف أو المستندات السرية إلا بنطاق موثق ومعلن.

## عزل المستأجرين

- اشتراط company/group context في كل وصول لبيانات العمل، وإثبات عضوية المستخدم النشطة.
- مفاتيح أجنبية مركبة عند الحاجة لمنع ربط سجلات من منشآت مختلفة.
- تفعيل RLS كطبقة دفاع إضافية، مع اختبارات سلبية بين مستأجرين لكل جدول/وظيفة.
- لا يتم تغيير المنشأة النشطة عبر قيمة يرسلها العميل وحدها؛ تتحقق العضوية على الخادم.
- تشمل اختبارات العزل النسخ الاحتياطي والاستعادة والبحث والتصدير والتقارير.

## التدقيق والخصوصية

- تسجيل الفاعل والمنشأة والسياق والفعل والسجل والقيم السابقة/الجديدة والنتيجة والوقت.
- تقييد تعديل/حذف سجل التدقيق على مستوى قاعدة البيانات؛ فصل صلاحية العرض عن التصدير.
- تشفير النقل والتخزين والنسخ الاحتياطية وإدارة الاحتفاظ والحذف وفق المتطلبات المعتمدة.
- جمع GPS بموافقة صريحة ومحددة للمهمة، مرة عند الوصول فقط، مع حفظ غرض الجمع وفترة الاحتفاظ وعدم التتبع خارج المهمة.

## الاستجابة والتشغيل

- تدوير الأسرار، مراجعة صلاحيات الاستضافة، مراقبة الأخطاء، نسخ احتياطية مشفرة، وتجارب استعادة دورية.
- تطبيق ترقيعات الإطار الأمني قبل النشر، وإجراء مراجعة أمنية واختبارات اعتماد قبل الإنتاج.
- تحذير Next.js الوارد أثناء المعاينة الأمنية حاجز نشر حتى تتم ترقية معتمدة والتحقق من الإصدار والبناء.

هذه وثيقة تصميم وليست شهادة امتثال أو بديلاً عن مراجعة أمنية واختبار اختراق مصرح به. يجب اعتماد الدولة وسياسة الخصوصية والاحتفاظ قبل التنفيذ.
