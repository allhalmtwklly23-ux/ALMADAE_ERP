# التقنيات — مسودة المرحلة B

**الحالة:** مسودة للمراجعة والاعتماد

## الموجود حالياً

| الطبقة | التقنية الحالية |
|---|---|
| الويب | Next.js 16.4.2 App Router، React 19.3.0، TypeScript 5 |
| التنسيق | Tailwind CSS 4 عبر Turbopack |
| قاعدة البيانات | Supabase PostgreSQL و`@supabase/supabase-js` |
| تخزين التطوير | JSON محلي عند عدم إعداد Supabase |
| المصادقة | طبقة جلسات ERP خاصة، بحسب المسار ووضع التخزين |
| الاختبارات | Node test scripts وTypeScript وESLint |
| الاستضافة المقترحة في README | Vercel، لكن لا يوجد remote أو إعداد نشر مثبت في المستودع |

## الاتجاه المقترح

- **التطبيق:** الاستمرار على Next.js/React/TypeScript ما دامت واجهة الويب هي المنتج الأساسي.
- **قاعدة البيانات:** PostgreSQL مع migrations قابلة للتكرار، نماذج علائقية للنواة والعمليات، واستخدام JSONB بحذر للامتدادات المرنة.
- **الوصول:** عميل Supabase خادمي فقط للخدمات الإدارية؛ واجهات المجال هي طبقة التفويض والتعامل مع المعاملات.
- **المصادقة:** اعتماد قرار موحد بين الجلسات الحالية وSupabase Auth بعد تحليل الترحيل وMFA، وعدم تشغيل نظامي مصادقة متوازيين دون حاجة موثقة.
- **المرفقات:** اختيار تخزين كائنات خاص مع روابط مؤقتة وسياسات وصول بعد اعتماد المتطلبات.
- **الجودة:** إضافة أمر اختبار موحد، وفحوصات CI لـlint/typecheck/tests/build، واختبار migrations على قاعدة اختبار.
- **التشغيل:** بيئات منفصلة للتطوير والمعاينة والإنتاج، وإدارة الأسرار من لوحة الاستضافة، ومراقبة ونسخ احتياطي مجرب.

## القيود الحالية

- لا يوجد أمر `test` موحد في `package.json`؛ اختبارات TypeScript تعتمد حالياً على دعم Node لتجريد الأنواع عند التشغيل.
- المستودع لا يحوي remote أو commits، ولذلك لا يوجد نشر مستمر أو دليل على إعداد CI.
- لا يمكن اعتبار JSON المحلي قاعدة بيانات إنتاج متعددة الخوادم.
- schema SQL القديم لا يطابق بالكامل نموذج migrations الفعلي؛ يلزم حسم مخطط البيانات في المرحلة D قبل اعتماد مسار جديد.
- تشغيل معاينة التطوير أظهر تنبيهاً من Next.js بوجود توصية أمنية للإصدار الحالي. يلزم اعتماد الترقية ثم إعادة lint/typecheck/tests/build قبل النشر. لم تُنفذ الترقية.

2. منصة النشر والـpreview domains وبيئات قاعدة البيانات.
3. مكان ملفات الوثائق والمرفقات.
4. سياسة مراقبة الأخطاء والنسخ الاحتياطي والاستعادة.
5. دعم التطبيقات الجوالة أو العمل دون اتصال ضمن النطاق الأول.

لا تضف مكتبات أو تغير الإصدارات في هذه المرحلة الوثائقية.
